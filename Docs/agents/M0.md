# Agent Runbook — M0: Foundations

> **You are executing ONLY Milestone M0** of this project. Do not start M1 or any
> later work. When M0's acceptance checks pass, STOP and report back.
>
> **Goal of M0:** the FastAPI backend runs locally, connects to Supabase Postgres,
> and `GET /health` returns green. Nothing more.
>
> Source of truth: `Docs/BUILD_PLAN.md`, `Docs/PROJECT_BRIEF.md`, `Docs/TODO.md`.
> This file is the *how-to-run-M0*; the plan docs hold the *exact specs*.

---

## 0. Operating rules (non-negotiable)

1. **No hallucination.** Do not invent file contents, column names, endpoint shapes,
   library names, values, or model IDs. Every artifact you create must trace to a
   specific section of `BUILD_PLAN.md`. If a detail is not in the docs, do **not**
   guess — see rule 3.
2. **Read the docs first, act second.** Before writing any file, open and read the
   referenced `BUILD_PLAN.md` section for that file. Build from the doc, not from memory.
3. **If something is unknown or unresolved, STOP and ASK the user.** Do not proceed
   past a blocking gap by guessing. The known blocking items are listed in §1 below;
   if you hit any *other* ambiguity, ask rather than assume.
4. **Secrets are user-supplied.** Never fabricate `DATABASE_URL` or `ANTHROPIC_API_KEY`.
   Never print them, commit them, or place them in code/frontend. `.env` must be gitignored.
5. **Stay in scope.** M0 touches only: `db/schema.sql`, `backend/` scaffold, `.env`
   files, and a minimal `main.py` with `/health`. Do NOT build the rule engine, intent
   check, anomaly score, endpoints beyond `/health`, or any frontend. Those are M1+.
6. **Do not commit or push** unless the user explicitly asks. If asked later, the
   security review (`BUILD_PLAN §14`) must run first.
7. **Verify, don't assume.** An acceptance check is passed only when you have actually
   observed the stated result (e.g. a real 200 response), not because the code "should" work.

### 3.3 Backend dependencies & env (`BUILD_PLAN §7`, `§10`)
- [ ] Create `backend/requirements.txt` with exactly: `fastapi`, `uvicorn[standard]`,

### 3.4 Backend scaffold (`BUILD_PLAN §7`, `§8`)
Create these four files, each matching its `BUILD_PLAN §7` responsibility:
- [ ] `backend/config.py` — load `DATABASE_URL`, `ANTHROPIC_API_KEY` via `python-dotenv`;
      expose `LLM_CONFIGURED = bool(ANTHROPIC_API_KEY)`.
- [ ] `backend/database.py` — SQLAlchemy `engine` from `DATABASE_URL`, `SessionLocal`,
      and a `get_db()` FastAPI dependency.
- [ ] `backend/models.py` — `Agent` and `Transaction` ORM classes **matching
      `db/schema.sql` column-for-column** (`BUILD_PLAN §4`). Do not invent fields.
- [ ] `backend/main.py` — minimal FastAPI app: instance (with the confirmed `title`),
      CORS restricted to `http://localhost:5173`, and **only** `GET /health` returning
      `{"status": "ok", "llm_configured": <bool>, "db_connected": <bool>}` where
      `db_connected` is the result of a trivial `SELECT 1` against the DB. Match the
      `/health` contract in `BUILD_PLAN §8` exactly. **Do not add other routes in M0.**

> If any file's spec is unclear in the docs, STOP and ask — do not fill the gap by guessing.

### 3.5 Run it (`BUILD_PLAN §11`)
- [ ] Start the backend: `uvicorn main:app --reload --port 8000` from `backend/`.
      (First boot will error if `DATABASE_URL` is wrong — treat that as a real signal,
      report the exact error to the user, do not paper over it.)

  cannot do this UI step.

  connection string, pooler mode, SSL settings, or driver prefix — report the exact
  error and ask.

- Anything would require touching M1+ scope (rules, intent, anomaly, other endpoints,
  frontend) to make M0 "work" — that means the plan is being misread; stop and ask.
