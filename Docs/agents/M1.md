## 0. Operating rules (non-negotiable — same as M0)

1. **No hallucination.** Do not invent file contents, column names, endpoint
   shapes, reason strings, seed numbers, thresholds, or values. Every artifact
   must trace to a specific `BUILD_PLAN.md` section. If a detail is not in the
   docs, do **not** guess — see rule 3.
2. **Read the docs first, act second.** Before writing a file, open and read the
   cited `BUILD_PLAN.md` section. Build from the doc, not from memory.
3. **If something is unknown or unresolved, STOP and ASK the user.** Known
   blocking items are in the Precondition and §1 below; for any *other*
   ambiguity, ask rather than assume.
4. **Stay in scope.** M1 builds ONLY: `seed.py`, `schemas.py`, `rules.py`, a
   **rules-only** `policy_engine.py`, and the endpoints `POST /evaluate-transaction`
   (rules-only), `GET /agents`, `GET /transactions`, `POST /reset`, plus startup
   seeding. Do **NOT** build intent match, anomaly score, escalation UI, or any
   frontend — those are M3/M4/M2.
5. **Do not commit or push** unless the user explicitly asks. If asked, the
   security review (`BUILD_PLAN §14`) must run first (payments/DB/inputs are touched).
6. **Verify, don't assume.** An acceptance check passes only when you have
   actually observed the stated result (a real HTTP response / real DB row), not
   because the code "should" work.

## 2. Task list — M1 (do in order; mirrors `TODO.md §3`)

For each file, the exact spec lives in the cited `BUILD_PLAN.md` section — read it,
then build to match. Do not deviate from column names, seed numbers, reason strings,
thresholds, or endpoint shapes.

### 2.1 Seed data (`BUILD_PLAN §5`, §4)
- [ ] Create `backend/seed.py` with `seed(db)` / `reset(db)` that:
      - wipe `transactions`;
      - upsert the **four canonical agents** with the **exact** ids/names/tasks/
        budgets from `BUILD_PLAN §5` (Founder ₹5,000, Developer ₹6,000, Research
        ₹800, Marketing ₹2,000);
      - insert the seeded history rows as prior **allowed** transactions with the
        exact amounts in §5 (Developer ₹40/₹55/₹35; Research ₹80/₹110/₹95;
        Marketing ₹250/₹300/₹280; Founder none), satisfying the NOT NULL columns
        per §1 above;
      - set each agent `balance = budget − sum(seeded spend)`.
      **Every number must match `BUILD_PLAN §5` exactly.**
- [ ] Wire startup seeding in `backend/main.py`: on startup, if the `agents` table
      is empty, call `seed(db)`. (Keep the existing `/health` route unchanged.)
- [ ] ✅ After boot, the `agents` table has exactly 4 rows with the budgets/balances
      implied by §5 (Developer balance ₹5,870, Research ₹515, Marketing ₹1,170,
      Founder ₹5,000).

### 2.2 Pydantic schemas (`BUILD_PLAN §8`)
- [ ] Create `backend/schemas.py` with `EvaluateRequest`, `ResolveRequest`,
      `AgentOut`, `TransactionOut`, `DecisionOut`, `HealthOut` matching the **exact
      JSON shapes** in `BUILD_PLAN §8`. Include validation: `amount > 0` and finite;
      `description` non-empty and length-capped. (`ResolveRequest` is defined now but
      is used in M4 — defining it here is fine; the `/resolve-escalation` route is NOT
      built in M1.)

### 2.3 Rule engine (`BUILD_PLAN §6.1`)
- [ ] Create `backend/rules.py::run_rules(agent, amount, description, db)` implementing,
      **in order**, the three checks in `BUILD_PLAN §6.1`: budget → blocklist → velocity,
      with the **exact** blocklist categories, the **5 tx / 10 s** velocity threshold,
      and the **exact reason strings** given in §6.1. Return `{passed, failed_rule, reason}`.
      Do not add or rename checks.

### 2.4 Policy engine — rules-only for M1 (`BUILD_PLAN §6.4`, §4)
- [ ] Create `backend/policy_engine.py::evaluate(...)` in **rules-only** form:
      - run `run_rules`; if it fails → `decision="deny"`, `triggered_by="rule_engine"`,
        `status="denied"`, reason from the rule result;
      - if rules pass → `decision="allow"`, `status="allowed"` (intent & anomaly are
        **not implemented yet** — record them in the `checks` JSONB as `"ran": false`,
        per the M1 note in `TODO §3` and the `checks` shape in `BUILD_PLAN §4`);
      - write **one** `transactions` row with the full `checks` blob (rule_engine result
        + intent/anomaly stubs), `triggered_by`, `intent_source=null`;
      - on `allow`, deduct `amount` from `agent.balance`; on `deny`, no deduction.
      Follow the combination logic and side-effects in `BUILD_PLAN §6.4` and §4.
      > NOTE: because intent/anomaly are stubbed as "did not object," scenarios 2 and 3
      > will resolve to **Allow** in M1 — that is expected; the differentiator arrives in M3.

### 2.5 Endpoints (`BUILD_PLAN §8`)
Add to `backend/main.py` (keep `/health`):
- [ ] `POST /evaluate-transaction` → calls `evaluate`, returns `DecisionOut`.
      Handle `404` unknown `agent_id`, `422` bad body. Match the §8 request/response exactly.
- [ ] `GET /agents` → roster with live balances (`AgentOut[]`).
- [ ] `GET /transactions?limit=50` → newest-first (`TransactionOut[]`).
- [ ] `POST /reset` → calls `reset(db)` → `{ "ok": true }`.
> Do **NOT** add `/resolve-escalation` (that is M4).
