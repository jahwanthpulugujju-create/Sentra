# Agent Runbook — M2: Frontend Skeleton

> **You are executing ONLY Milestone M2.** Do not start M3 or any later work.
> When M2's acceptance checks pass, STOP and report back.
>
> **Goal of M2:** a React + Vite dashboard (thin client) that renders the agent
> roster and the audit log from the backend, and can submit a transaction. It
> polls the backend every 2s so balances and the ledger stay live. **No policy
> logic in the browser** — the frontend only renders what the API returns and
> sends user actions.
>
> Source of truth: `Docs/BUILD_PLAN.md`, `Docs/PROJECT_BRIEF.md`, `Docs/TODO.md`.
> This file is the *how-to-run-M2*; the plan docs hold the *exact specs*.

---

## 0. Operating rules (non-negotiable — same as M0/M1)

1. **No hallucination.** Do not invent endpoint names, response fields, seed
   numbers, colors, component behavior, or values. Every artifact must trace to a
   specific `BUILD_PLAN.md` section (frontend = §9; endpoints = §8; demo data =
   §5). If a detail is not in the docs, do **not** guess — see rule 3.
2. **Read the docs first, act second.** Before building a component, read the
   cited `BUILD_PLAN.md §9` entry for it. Build from the doc, not from memory.
3. **If something is unknown or unresolved, STOP and ASK the user.** Known
   blocking items are in the Precondition and §1 below; for any *other* ambiguity,
   ask rather than assume.
4. **Thin client — no business logic in the browser.** The frontend must not run
   the rule engine, intent match, anomaly score, or the decision. It calls the
   backend and renders the result. (Core rule, `BUILD_PLAN §0`.)
5. **Stay in scope.** M2 builds ONLY: the Vite app, Tailwind setup, `theme.js`,
   `api.js`, and these components — `Header` (+ `HealthBadge`, `ResetButton`),
   `AgentRoster` + `AgentCard`, `RequestPanel`, `AuditLog` + `AuditRow`,
   `usePolling`, and `App`. Do **NOT** build the animated three-chip
   `ProcessingPanel`/`DecisionBanner` (that is **M3**) or the `EscalationCard`
   Approve/Deny flow (that is **M4**). See the scope note in §2.3.
6. **Do not commit or push** unless the user explicitly asks. (Frontend touches no
   secrets, but the same commit gate applies.)
7. **Verify, don't assume.** An acceptance check passes only when you have
   actually observed it in the running browser, not because the code "should" work.

## 2. Prerequisites & scope

### 2.1 Tooling (verify — do not assume; `TODO §0b`)
- [ ] ✅ Confirm `node --version` (need Node 18+) and `npm --version` work. If Node
      is missing/older, **STOP and ASK the user** to install Node 18+ — do not try
      to work around it.

### 2.2 Origin / CORS (already set in the backend)
- [ ] The backend CORS allows `http://localhost:5173` (the Vite default). Run the
      Vite dev server on **5173** so requests are not blocked. If Vite picks a
      different port, either free 5173 or tell the user (a CORS mismatch will show
      as failed fetches). Ref: `BUILD_PLAN §9`, `backend/main.py` CORS.

### 2.3 SCOPE BOUNDARY — read before building (prevents M3/M4 creep)
- In M2, clicking a preset calls `POST /evaluate-transaction` and the **result
  becomes visible via the audit log refreshing (polling)**. That is the intended
  M2 feedback.
- Do **NOT** build in M2: the animated three-chip processing pipeline, the
  `DecisionBanner` reveal animation (**M3**), or the `EscalationCard` with
  Approve/Deny (**M4**).
- **Expected M2 behavior caveat:** intent-match and anomaly are not built until
  M3, so in M2 the "hijack" preset (developer, ₹5,000, GPU cluster) will resolve
  to **Allow** (rules pass). That is correct for M2 — do NOT add logic to make it
  escalate; the differentiator arrives in M3.

## 3. Task list — M2 (do in order; mirrors `TODO.md §4`)

For each file, the exact spec lives in the cited `BUILD_PLAN.md` section — read it,
then build to match. Do not invent endpoint names, fields, or preset numbers.

### 3.1 Scaffold (`BUILD_PLAN §9`, §10, §11)
- [ ] Create a Vite React app in `frontend/` (React template; use the confirmed
      package manager).
- [ ] Install and configure **Tailwind CSS + PostCSS** (`tailwind.config.js`,
      `postcss.config.js`, base CSS). Ref: `BUILD_PLAN §9` (styling).
- [ ] Create `frontend/.env.example` and `frontend/.env` with
      `VITE_API_BASE=http://localhost:8000`. (`.env` is gitignored per `BUILD_PLAN §10`.)

### 3.2 Theme + API client
- [ ] `src/theme.js` — the palette tokens for the **confirmed** palette (§1). Default:
      navy `#0B1F3A`, amber `#F5A623`, semantic green/red. Keep it the single place
      colors are defined so the palette can be swapped once.
- [ ] `src/api.js` — thin fetch wrappers for **every endpoint in `BUILD_PLAN §8`**,
      reading the base URL from `VITE_API_BASE`: `getHealth` (`GET /health`),
      `getAgents` (`GET /agents`), `getTransactions` (`GET /transactions`),
      `evaluate` (`POST /evaluate-transaction`), `reset` (`POST /reset`), and
      `resolve` (`POST /resolve-escalation`). **Note:** the `resolve` wrapper is
      defined now but its route is not built until M4 — define it, don't call it in M2.

### 3.3 Components (per the `BUILD_PLAN §9` tree)
Build exactly these; match each component's described content/behavior in §9:
- [ ] `Header.jsx` — brand/title + `HealthBadge` (polls `GET /health`; green =
      connected+LLM, amber = no key, red = offline) + `ResetButton` (calls
      `POST /reset`). Use the confirmed project title (still a placeholder unless
      the user has named it — `PROJECT_BRIEF §1`; ASK if unsure).
- [ ] `AgentRoster.jsx` + `AgentCard.jsx` — a card per agent: name, task (muted),
      and a live budget bar (`balance`/`budget`). Data from `getAgents`.
- [ ] `RequestPanel.jsx` — four preset buttons for the **four canonical scenarios**
      (params EXACTLY from `BUILD_PLAN §5`; the 3rd is the big red "Simulate
      hijacked agent") + a custom builder (agent dropdown from the roster, amount,
      description, Submit). Submitting calls `evaluate`.
- [ ] `AuditLog.jsx` + `AuditRow.jsx` — newest-first list from `getTransactions`,
      color-coded by `status`; each row shows agent, amount, decision, reason,
      source, time.
- [ ] `hooks/usePolling.js` — poll `getAgents` and `getTransactions` every **2s**
      (`BUILD_PLAN §9`). Clean up the interval on unmount.
- [ ] `App.jsx` — compose Header, AgentRoster, RequestPanel, AuditLog; hold the
      polled state; pass it down.

## 6. When to STOP and ask the user (explicit gates)

Stop and ask — never guess — if:
- The backend isn't running or `/health` isn't `db_connected:true` (M1 unfinished).
- Node/npm is missing or too old (§2.1).
- The palette, package manager, project title, or "use my design output?" question
  (§1) is unresolved and you're unsure.
- A component's behavior, an endpoint field, or a preset's params isn't found in
  `BUILD_PLAN.md` (§9/§8/§5) — ask rather than invent it.
- Making an acceptance check pass would require building M3/M4 scope (processing
  animation, decision banner, escalation card) — that means the scope boundary
  (§2.3) is being crossed; stop.
- CORS/port issues can't be resolved without changing the backend origin allowlist
  — report and ask.
